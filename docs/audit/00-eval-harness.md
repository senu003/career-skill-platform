## 2. ML Models Breakdown

### SkillLevelPredictor
*   **Training Data**: 500 rows of purely *synthetic* data (`generate_synthetic_dataset`).
*   **Target Label**: `target_level` (basic, intermediate, advanced). Used as a latent variable to generate the score features with random noise.
*   **Exact Feature List**: `cv_matched`, `required_level`, `importance`, `basic_score`, `intermediate_score`, `advanced_score`, `total_score`.
*   **Metrics**: 5-Fold Stratified CV (Accuracy, Macro F1), and untouched 20% test set (Accuracy, Precision, Recall, F1, Confusion Matrix).

### Model 1: Skill Evaluator
*   **Training Data**: 1000 rows of *synthetic* data (`generate_model1_dataset`).
*   **Target Label**: `target` ("Mastered", "Upgrade Needed", "Speed Practice", "Re-learn Basics"). Generated by defining latent profiles which then output the features.
*   **Exact Feature List**: `jd_required_level`, `cv_parsed_level`, `basic_score`, `intermediate_score`, `advanced_score`, `assessment_score`, `avg_time_per_question`, `relative_time`, `attempt_count`, `previous_best_score`, `score_gap`, `speed_accuracy`.
*   **Metrics**: 5-Fold Stratified CV, untouched 20% test set (Accuracy, Precision, Recall, Macro F1, ROC-AUC).

### Model 2: Final Recommendation Engine
*   **Training Data**: 600 rows of *synthetic* data (`generate_model2_dataset`).
*   **Target Label**: `target` ("Interview Ready", "Short-Term Prep", "Major Upskill Required").
*   **Exact Feature List**: Derived via `extract_model2_features` (e.g., `total_required_skills`, `missing_skills_count`, `average_skill_gap`, `overall_assessment_accuracy`, `mastered_count`, `relearn_basics_count`, `upgrade_needed_count`, etc.).
*   **Metrics**: 5-Fold Stratified CV, untouched 20% test set (Accuracy, Precision, Recall, Macro F1, ROC-AUC).

## 3. Leakage and Safety Overlap Flags

**FLAG: Massive Target Leakage in Model 2:** The training label for Model 2 is computed using `compute_composite_verdict_target`, which applies a deterministic heuristic formula (involving missing ratio, gap sizes, accuracy, etc.) to the features to generate the ground truth. Meanwhile, the `predict_readiness.py` script applies a *Deterministic Safety Layer* built on almost identical rules (e.g., if missing ratio > 75%, override to "Major Upskill Required"). Because the synthetic data's label is derived from these rules, the ML model is simply memorizing a hardcoded formula. The ML and the safety layer are completely coupled.

**FLAG: Latent Label Generation in Model 1 and SkillPredictor:** The labels for these models are latent states used to *generate* the feature scores. In production, we predict the label from the scores. Because the data isn't from real human behavior, the models evaluate perfectly on their own synthetic generative logic, but we have no proof they generalize to real humans.

## 4. End-to-End Pipeline Entry Points (No HTTP)

To run the pipeline in a test harness without starting the FastAPI server, the following Python functions should be called sequentially:
1.  **Extract Text**: `extract_pdf_text(file_path)` (from `app.services.cv_service`)
2.  **LLM Matching**: `evaluate_cv_with_gemini(cv_text, parsed_requirements)` (from `app.services.requirement_service`)
3.  **Basic Scoring**: `calculate_skill_score(matched, missing)` (from `app.services.scoring_service`)
4.  **Assessment Merge**: `combine_cv_and_assessment(cv_matching_result, db, user_id)` (from `app.services.skill_analysis_service`)
5.  **Final Verdict**: `predict_final_recommendation(combined_result)` (from `app.ml.predict_readiness`)

## 5. Gemini Caching for Repeatability

Currently, `evaluate_cv_with_gemini` makes direct network calls without a caching layer. To make the eval harness repeatable and fast, we must implement a caching wrapper (e.g., hashing the `cv_text` + `parsed_requirements` to a JSON file). Additionally, we need to ensure the Gemini model is explicitly called with `temperature=0` to guarantee deterministic output across runs.

## 6. Missing Components for the Evaluation Harness

To build a functional eval harness with 30-50 pairs, we are currently missing:
1.  **Labeled Ground Truth Dataset**: A JSON or CSV mapping 30-50 specific CV PDFs to Job Requirements, along with human-annotated expected outputs (Expected Matched Skills, Expected Missing Skills, Expected Final Verdict). The current PDFs in `uploads/` are unlabeled.
2.  **Caching/Mocking Layer**: A decorator or wrapper for `evaluate_cv_with_gemini` to intercept LLM calls and save/load them from disk.
3.  **Harness Execution Script**: A script that iterates over the labeled dataset, calls the entry points directly, and calculates evaluation metrics (Precision/Recall for skill matching, Accuracy for the final verdict).
